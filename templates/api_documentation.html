Authentication

LifeLink service requests must send: Authorization: Bearer <LIFELINK_API_SECRET>

Endpoints

MethodEndpointPurpose
GET/api/v1/inventoryFetch eligible available inventory
GET/api/v1/inventory/availabilityGet aggregate available units without deduction
POST/api/v1/inventoryAuthorized inventory creation
PUT/api/v1/inventory/{id}Authorized inventory quantity update
GET/api/v1/blood-bank/profilePublic blood bank profile

For inventory creation, omitted component type defaults to Whole Blood, collection date defaults to donation date, and expiry defaults to 42 days after donation date.

Example Availability Request

GET /api/v1/inventory/availability?blood_group=O%2B&city=Mangaluru
Authorization: Bearer YOUR_API_SECRET
{
  "success": true,
  "blood_group": "O+",
  "city": "Mangaluru",
  "component_type": "Any",
  "total_available_units": 5,
  "blood_bank": {"name": "Demo Blood Bank", "city": "Mangaluru"}
}

Python requests example

import requests

response = requests.get(
    "https://blood-bank.example/api/v1/inventory/availability",
    params={"blood_group": "O+", "city": "Mangaluru"},
    headers={"Authorization": "Bearer YOUR_API_SECRET"},
    timeout=10,
)
response.raise_for_status()
availability = response.json()

Error Responses

401 {"success": false, "error": "Unauthorized"}
400 {"success": false, "error": "blood_group is required"}

Availability checks are read-only and never deduct stock. Reservations and confirmed transactions must use a separately authorized workflow and update inventory atomically.
